# Standalone QQ Chat Import Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:test-driven-development for code changes. Keep the import path independent from runtime Agent tools.

**Goal:** Replace the old reviewed QQ import state machine with a standalone trusted-source script that imports raw QQ conversation chunks into MemOS.

**Architecture:** `plugins/memos-client/scripts/qq-memos-import.ts` owns CLI parsing, QQ JSON parsing, filtering, de-duplication, chunking, MemOS request construction, dry-run summaries, and live HTTP writes. Operators run this TypeScript file directly with `tsx`; no wrapper or package script is added. `plugins/memos-client` keeps runtime search/add tools but no longer owns a historical import workflow.

**Identity architecture:** MemOS ids are generated by shared `plugins/memos-client` identity code. `user_id` identifies the chat subject and excludes bot `selfId`; `conversation_id` identifies a runtime turn or import chunk; `agent_id` identifies the bot by `platform + selfId`. Runtime search uses subject `user_id` without the current `conversation_id` by default so it can retrieve imported chunk contexts.

**Tech Stack:** TypeScript, Node built-ins, fetch, Vitest, Yarn 4, MemOS Cloud `POST /add/message`, OpenSpec `superpowers-bridge`.

## Global Constraints

- Use `rtk yarn`, not `npm` or `pnpm`.
- Do not embed real operator export paths, bot ids, group ids, group names, or contact names in source or tests.
- Require `--input` and `--bot-self-id`.
- Use `--dry-run` for local-only planning; dry-run must not require `MEMOS_API_KEY` or call MemOS.
- Live import requires `MEMOS_API_KEY`; never print it.
- Directory input is non-recursive and scans only direct `*.json` files.
- Default chunk limits are `16000` estimated tokens, `400` messages, `168` hours, and `0` overlap messages.
- Keep bulk import out of Agent-visible tools.
- Keep MemOS identity generation shared between runtime tools and the import script; do not copy hash algorithms into the script.
